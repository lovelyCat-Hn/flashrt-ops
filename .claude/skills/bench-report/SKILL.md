# BENCHMARKS.md 数据报表撰写规范

## 1. 定位（先读）

- `~/holy/BENCHMARKS.md` = **论文级数据报表**，读者是外部技术读者。只收三样东西：
  **数据表 + 测量条件 + 复现命令**。
- **禁止入内**：判读、机制解释、工程含义、归因叙事、下一步计划。这些进记忆库
  （agent_memory/，走三件套流程）；报告只留"结论档位"级别的判定（拒收/采用候选/在用）。
- **数据分流**：现役定档与现行口径 → BENCHMARKS.md；被推翻的结论与旧时代数据 →
  `BENCHMARKS_ARCHIVE.md`（顶部 ⚠ 标注防误引）。

## 2. 数据流水线（铁律，先于一切写作）

1. **探针/基准的 stdout 必须当场落盘**：`evidence/YYYYMMDD_主题/`，含运行命令、
   条件、原始输出。目录配 README.md 说明条件与文件清单。
   - 反面教材：2026-10-06/07 的逐层 K/V cos 表和 module_timing_probe.py 都只活在
     /tmp 与会话记录里，10-07 整机重启后靠从 transcript 逐字抢救才保住
     （现存 `evidence/20261006-07_quant_kv_ablation/`）。transcript 不是存储。
2. 报告里每张表注明数据来源（evidence 路径或日志路径）；能让读者复现的命令进 §八复现索引。
3. 脚本本身进 `scripts/probes/`（或 benchmarks/），不留在 /tmp。
4. 新数据进来先问一句：它属于当前定档/现行口径吗？是 → 本报告对应表；它推翻了
   表里某行 → 更新该行 + 旧值移 ARCHIVE（或表内标注"史档"）。

## 3. 表格规范（借鉴 booktabs 三线表 / ML 论文 bold-best / PMC 数字精度建议）

1. **表自足**：不看正文也能懂。条件写在表题下一行：日期、机型、模型/ckpt、
   帧集、样本数 n、模式（NO_GRAPH / graph-on / --nav-suspend 等）。
2. **单位进表头**（ms、µs、mrad、pp、GB/s），不进单元格。
3. **有效位全列统一**：延迟一位小数 ms、cos 四位小数、pp 两位、时间整秒。
4. **基线行放第一个数据行**；最优/在用行加粗；粗体只用于这两处，不做强调装饰。
5. 汇总行（合计/p50/每推理折算）与明细行视觉区分（加粗或缩进符号 └）。
6. **口径注脚**：不同探针/环境的绝对值不可跨口径比，delta 只在同口径内比。
   凡有此风险的表必须加 ⚠ 注脚（例：rot 探针含 ~30ms 采集 instrumentation；
   tf-cos 基线 10-06 批 0.949 vs 10-07 批 0.683 跨批不可比）。
7. 缺数写 `—`（未测）或 `×`（不适用），**不编造、不倒推**。预估/外推值必须标
   "（估）"并单列一表（如表 2-4 编码器降载杠杆），不与实测混排。
8. 结论列只写档位（拒收/采用候选/在用/基线/待 A/B），理由不进报告。
9. 逐层/逐项明细表：数值有信息量就全列（如 KV cos 逐层表）；全 1.0000 的
   sanity 表可压缩成一行 + 指向 evidence 原表。
10. 一节 = 一个主题，表编号 节-序（表 3-2）；条件相同的连表共用一个条件块。

## 4. 更新流程

1. 落盘 evidence → 2. 加表/改表（按 §3 规范）→ 3. 刷新 §〇速览对应行 →
   4. `git commit`（结尾 `Co-Authored-By: Claude Code <noreply@anthropic.com>`，push 走 SSH）。
5. 若新数据推翻了记忆里的结论 → 同步走记忆三件套（细节文件 + MEMORY.md +
   OVERVIEW）更新 agent_memory/；报告里只留数据，不留"以前错在哪"的叙事。
