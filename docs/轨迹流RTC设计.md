# G1 轨迹流式执行 RTC 设计（run_g1_loop_traj.py：推理侧引导 + 执行侧流式）

调度约定出处：Physical Intelligence *Real-Time Chunking* + lerobot `src/lerobot/policies/rtc/`（Apache-2.0）。与 `run_g1_loop.py`（合步线，见 `docs/执行侧RTC设计.md`）的本质区别：那条线 RTC **只做执行侧**（hold 等待调度），本线**推理侧也做了**——FlashRT 引擎逐去噪步前缀引导（guided RTC），执行侧换成固定节拍高频流式。执行链路移植自同事 `infer_policy` 真机在役实现（样条/EMA/skip-frame 同源）。

---

## 1. 解决什么问题

pi0.5 每轮推理输出一条 chunk（50 行 @30Hz = 1.67s 计划），真机单轮推理 ~330ms。流式执行 = 固定 tick（1/30s）逐行下发 `set_joint_commands`，消费到水位（n_action_steps）即预取换块。两个结构性坑：

| 坑 | 根源 | 后果 |
|---|---|---|
| **块界接缝** | 新块计划与臂当前态失配：重规划跳变 ∝ 观测陈旧度（快照→落地隔 ~10 拍） | 接缝 p50 135 / max 348 mrad（健康谱定案）；臂在块界减速→冲刺脉动 |
| **回溯段** | 新块行 0 是模型对"拍摄时刻→落地"已走时隙的重绘 | 消费它 = 块界「减速→冲刺」的构造性根源 |

RTC 在**两头**各修一层：推理侧让新块计划头几行贴着旧计划生成（计划层无跳变），执行侧让参考链跨界连续（发令层无跳变）。

## 2. 双层架构总览

```
推理侧（计划层，--rtc-horizon > 0 启用）
  旧块未消费尾段 → 重锚进新块 delta 坐标系（_rtc_prefix）
  → 引擎每个去噪步把隐含干净块往前缀拉（线性权重坡降）
  → 新块头 horizon 行天然与旧计划衔接 → 接缝在生成时就被压掉

执行侧（发令层，常开）
  固定 30Hz tick 逐行下发 + 链式限幅（每行至多挪 ±delta_max）
  + 换块可选搭接（--blend）/ 墙钟对齐跳帧（--skip-install）/ 平移（--ref-offset）
```

两层独立可开关：`--rtc-horizon 0`（默认）= 纯执行侧；叠加属双重消缝，A/B 时分开评估。

## 3. 推理侧 RTC（本文重点）

### 3.1 引导原理（lerobot guided mode）

引擎（`FlashRT/flash_rt/models/pi05/pipeline_rtx.py`）：**每个去噪步**把隐含干净块 `x1 = x − t·v` 往调用方给的归一化前缀（= 旧块未执行尾段）拉，前 `rtc_horizon` 行**线性权重坡降**（首行权重最大，行号越靠后拉力越小，`rtc_max_weight` 封顶）。效果：新块头 10 行是"旧计划的平滑延伸"，而不是与旧计划无关的全新采样。

### 3.2 FlashRT 落地形态（零额外开销）

- horizon / 权重 / 维数是**构造期参数**：逐步常量与 (chunk, 32) 权重图直接烘焙进 CUDA 捕获图；
- 每次调用只换**前缀内容 + rtc_enable 旗标**（流式上传）；`enable=0` 时该步与普通残差加位等 → **一张捕获图服务开/关两态**；
- 依赖 flash_rt_kernels 提供 `pi05_rtc_guided_residual` 算子（缺则构造期 fail-fast）。

### 3.3 前缀构造（`_rtc_prefix`，脚本侧每轮预取时调用）

```python
delay = max(0, min(round(infer_p50 / tick), WMARK))   # inference_delay：快照→落地隔几拍
j0 = k + delay                                        # 前缀窗口右移 delay 拍
pf[:, :7]  = chunk[j0:][:, :7]  + BASE_ARM[:7]  - new_base[:7]   # 臂维重锚：
                                                       # 绝对构型差（换 delta 基准）
pf[:, 7]   = chunk[j0:, 7]                            # 夹爪维原值携带（数据集语义=绝对 0-100）
若 len(pf) < horizon: hold-pad（重复末行）            # 零填充会解码到数据集均值
若块耗尽 / RTC 关: 返回 None                          # 引擎 enable=0 短路，该块免引导
```

三个关键点：

1. **重锚公式**：前缀必须是"绝对构型在新块坐标系下的差"——新旧块各自有 delta 基准（预测时刻臂位 `BASE_ARM` / `new_base`），直接搬原始 delta = 基准错位。
2. **inference_delay 右移（10-09 修正，此前误读设 0）**：前缀快照在抓帧时刻，而引导的新块要 ~10 拍后（推理 330ms ÷ 33ms）才落地执行；期间旧块尾段照常下发，**臂已物理走过前缀描述的区域**——不右移则每次换块都引导新块"倒退"回已走过的 ~10 拍（141706 实证：接缝 251 mrad ≈ 方向反转，与 RTC 关无异）。延迟拍数 = 推理 p50 ÷ tick，**在线动态估计**，非写死。
3. **快照时机**：预取在水位处 `job.start(..., rtc_prefix=_rtc_prefix(new_base))`——前缀与本次观测**同帧取关节读数**（与 job 存下的 delta 基准同源），保证重锚用的两个基准严格同一时刻。

### 3.4 效果（真机三态 A/B，2026-10-09，BENCHMARKS §八）

| 配置 | 接缝 p50 |
|---|---|
| RTC off | 57.2 mrad |
| **rtc-horizon 10**（lerobot 默认窗口） | **20.7 mrad** |

## 4. 执行侧（固定节拍流式）

- **时间纪律**：绝对节拍 `next_t += TICK`，落后 >1 tick 直接从当前态重锚，**永不追拍补发**（补发=突发冲击）；
- **链式限幅**：`rows[k] = rows[k−1] + clip(chunk绝对目标 − prev, ±delta_max)`——每行至多向计划挪这么多，块界无论怎么跳，发令增量被钳住；
- **星饿保护**：块耗尽且推理未归 → **不下发 = 伺服保持**（不续航旧块深尾）；超 `--starve-limit`（2.0s，≈正常推理 6× 余量）停机；
- **帧突发**：`--frames-per-row` 默认 1 = 纯 30Hz 直发（240Hz 微流已退役勿再用）；行导程 < `GAP_EPS`(1e-4) 免发拍；
- **样条**：`--interp cubic`（natural 样条 C2 连续无冲击），帧包络钳位。

换块参考链处理（四态谱：追回回摆 / anchor 停车 / delay 攒滞后猛冲 / **blend 连续跨界**）：

| 机制 | 语义 | 状态 |
|---|---|---|
| `--blend`（`--blend-gate 0.06`） | 新块前 M 行不发原目标，改发旧链末目标直连 rows[M−1]（M 自适应=计划首次爬回旧链高度的行号+1）；1:1 替换不加拍 | **定案最优**：残差 75.5 vs anchor 97 / 基线 69，无回摆模式 |
| `--skip-install` | 换块丢掉「拍摄→落地」流逝拍数行 + 链从 last_tgt 接续（同事 rtc_controller.skip_frames 墙钟对齐同款） | 备选，默认关 |
| `--ref-offset` | 整条新计划平移 offset=last_tgt−plan[0]（逐维钳 ±delta_max）再接链——块首零缝步零回走 | 备选，默认关 |
| EMA `--ema-alpha` | 行目标低通，状态跨块连续；**换块时状态重置为 last_tgt 重播**（修复：旧版存全链尾×水位弃尾 → 块首瞬移 294 mrad p90） | 默认 0 关；A/B 杠杆 |

## 5. 换块如何修复摆动（两层协同）

摆动根源 = 新块计划与臂当前态失配 + 参考链跨界跳变。本线两层各消一半：

1. **计划层（推理侧引导）**：新块头 10 行以线性衰减权重贴旧计划生成——跳变在**生成时**被压掉，接缝源头消除（§3.4：57.2→20.7 mrad）；
2. **发令层（执行侧）**：链式限幅钳住任意残余跳变；blend 让参考链全程前向直连（臂不停车不回摆，消回溯俯冲与块首急停）；
3. **观测新鲜度仍是第一杠杆**（10-10 水位 10 破局跑：重规划跳变 ∝ 观测陈旧度）：`--n-action-steps 10` 早预取 = 快照更新鲜 → delay 拍数少 → 引导更贴身；RTC 抹的是剩余量。引导右移 delay 拍（§3.3-2）保证"贴"的是臂**将要**到达的区域而非已走过的。

## 6. 速度怎么衔接

本线**没有显式配速**（那是合步线 `speed_rad_s` 的东西）：电机层是指数追踪（`set_joint_commands` tfs=0 尽快到达语义，无配速概念），速度完全由**计划行距密度**决定——行密→gap 小→追踪速度低，天然平滑。因此速度衔接 = 计划连续性：

- **块内**：样条 C2 连续（加速度连续无冲击），30Hz 直发节奏均匀；
- **块界**：推理侧引导保证新旧计划头尾衔接（计划速度场连续）+ blend 保证参考链跨界零跳变（发令不产生速度阶跃）；
- **星饿→恢复**：伺服保持=速度归零后从当前态重锚，链式限幅首行钳幅，无起步猛冲；
- **免发拍**：导程 <GAP_EPS 的拍直接跳过，无零速抖振。

（对比：合步线速度是执行侧"造"出来的——配速律在线反推；本线速度是计划"带"出来的——执行侧只保真转发。两条线的接缝问题因此长在不同层。）

## 7. 参数表

| 参数 | 默认 | 语义 |
|---|---|---|
| `--rtc-horizon` | 0（关） | 推理侧引导窗口行数；lerobot 默认 10；**在役必带 10** |
| `--rtc-max-w` | 10.0 | 引导最大权重（lerobot max_guidance_weight） |
| `--n-action-steps` | config [loop]=25 | 预取水位（消费到第 K 步触发新推理）；本线只定换块时机，非消费配额；**在役 CLI 传 10**（快照更新鲜→引导更贴身） |
| `--delta-max` | config [loop]=0.3 | 链式限幅 rad/行；**在役 CLI 传 0.05**（对原始增量 0.00% 截断=封版） |
| `--fps` | 30 | 行节拍；>40 拒绝（tick 低于取图+SDK 硬开销 ~25ms 必丢拍）；**勿改** |
| `--frames-per-row` | 1 | 插值帧数；**1=定案，勿调**（>1 仅留 A/B） |
| `--burst-reserve-ms` | 6.0 | tick 内留给读关节/换块的毫秒（在役配方 reserve 0） |
| `--interp` | cubic | 行间样条（linear/cubic/quintic） |
| `--ema-alpha` | 0.0 | 行目标低通（0=关；换块 last_tgt 重播已修） |
| `--blend` / `--blend-gate` | 关 / 0.06 | 前向搭接 / 触发门 rad（>60 mrad 滞后才搭） |
| `--skip-install` / `--ref-offset` | 关 / 关 | 墙钟对齐跳帧 / 整计划平移 |
| `--starve-limit` | 2.0 | 星饿停机阈值 s |

在役组合（10-13 定案）：`--rtc-horizon 10 --delta-max 0.05 --burst-reserve-ms 0 --n-action-steps 10` + `--grip-state-cmd`。

## 8. 已知边界

- **tfs 勿动**：tfs=0（尽快到达）是终审在役值；tfs33.3 实证 stall（SUCCESS 但臂不动，黑盒无契约）；≈帧间隔的 tfs 即限速到帧节奏，另一套律。
- 引导与 blend 叠加属双重消缝，单独 A/B 再合。
- 引导只压"计划连续性"；观测陈旧度才是接缝第一杠杆，别用 rtc-horizon 硬补陈旧观测（horizon 拉长=引导过强，新块机动性被旧计划锁死）。
- 推理侧引导需 kernels 带 `pi05_rtc_guided_residual`（重编 .so 须 env nvcc 11.8）；`--rtc-horizon 0` 时引擎 rtc=False 构造，无此依赖。
- 块界四态谱（§4）执行侧已到头；残余抖动=模型输出本身（相邻行翻转实测 ~109 次/s），根治在训练侧（lerobot pi05 trained-RTC / 数据侧）。
