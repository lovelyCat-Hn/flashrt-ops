# G1 闭环执行侧 RTC 设计（run_g1_loop.py 追踪式合步引擎）

调度约定出处：Physical Intelligence *Real-Time Chunking* + lerobot `src/lerobot/policies/rtc/`（Apache-2.0）的**执行侧**（extension/等待）。去噪引导层（denoise_step 前缀引导）**未搬**——需 per-ODE-step 钩子 + autograd 穿注意力，与 CUDA graph 捕获冲突，且本链路 delay≈1 轮收益有限（2026-10-04 评估）。即：**RTC 只做了执行侧，推理侧没做**。参数命名与 lerobot 术语对照见 `docs/lerobot-alignment.md`。

---

## 1. 解决什么问题

pi0.5 每轮推理输出一条 chunk（50 行动作，训练原生 30Hz 采集，即 1.67s 的运动计划）；真机单轮推理 ~320ms（bf16，导航栈冻结口径），远大于 1/30s。三种朴素执行法的坑：

| 朴素做法 | 坑 |
|---|---|
| 逐步阻塞下发（到位再发下一条，`--chunk-mode settle`） | 每点全停 → 速度曲线锯齿（"卡卡的"根因），提速只会加剧冲击（冲击∝速度） |
| 推理迟到后继续喂旧 chunk 剩余步"续航"（`--late-action stale`） | 深尾是衰减/反转的计划垃圾：臂往复 + 夹爪翻摆 500+ mrad（9/30 sweep 0.40/0.38 破位实录） |
| 整块轨迹 PVT 一次下发 | 每点全停更严重 + 换块跳变，已封存 |

本设计 = **合步 + 比例配速 + hold 等待调度** 三件套，方案A：`robot.set_joint_positions` 控制机械臂执行 chunk、主动下发关节速度。

## 2. 执行管线（一轮的生命周期）

```
取图+读关节（~22ms，主线程）→ 推理（后台线程，~320ms）
  → chunk[50]（臂维是 delta，基准=该块预测时刻臂位 BASE_ARM）
  → 消费前 n_action_steps=25 步（合步 spc=25 → 整轮 1 条 SDK 指令）
  → 下轮推理藏进首条指令执行期（观测取自滑行中途 = 真实当前态）
  → 消费配额完毕时新块早已就绪 → 立即换块零等待
```

- 每轮只消费前 25 步，剩余 25 步**永不喂**（弃尾）——深尾不进执行链。
- 换块时 `BASE_ARM = job.state_arm`（新块预测时刻臂位），闭环每轮从真实状态重规划。

## 3. 合步 + 比例配速律（方案A 核心）

每条指令（消费 chunk 步 [k, k_end)）：

```python
tgt = cur + clip(BASE_ARM + chunk[k_end-1] - cur, ±BUDGET)   # BUDGET = spc × delta_max
gap0   = max|tgt − cur|        # 导程：read_joints 读回来的最远关节距离（rad），
                               #   每条指令发令瞬间实测重算（执行轮更新，非推理轮）
pace_v = max(V_MIN, min(gap0 / (div_eff × pace), args.speed))
                               # 比例配速：速度 = 导程 ÷ (覆盖率旋钮 div × 窗口 pace)，
                               #   在线反推该段导程的配速
robot.set_joint_positions(tgt, speed_rad_s=pace_v)   # 显式下发目标位置+速度
```

**速度律**（原速点的充要条件是 `div × pace = n/30`，30Hz 是数据集真实采集频率）：

```
模拟频率 = n / (pace × div)  Hz        超频倍数 = 模拟频率 / 30
```

例（真机实测）：

| 配置 | 模拟频率 | 超频 | 结果 |
|---|---|---|---|
| n=25, pace=0.33, div=1.3 | 25/(0.33×1.3)=58.275Hz | **1.94×** | 11s 极限结果（该配置跑的） |
| n=25, pace=0.35, div=1.5（现役 v3） | 25/(0.35×1.5)=47.619Hz | **1.58×** | 14s 视频结果（该配置跑的） |

**div 的语义**（速度衔接的关键）：
- `div=1`：每窗走完全程导程 → 臂到点、速度过零 → 下一条指令重新起步 = 指令边界换向抖动；
- `div=2`：每窗走半程 → 臂**恒在途永不到点**，窗口末被下一条指令滑行重定向，**速度不过零、无到达门**——平滑靠永不到点，而非提速（0.6 提速实测更抖）；
- 1<div<2 = 按比例走导程，闭环重规划自校正滞后。

`V_MIN=0.02 rad/s` 下限：驻停时缓爬不僵死；`args.speed` 上限封顶。

## 4. pace 水位（推理等待调度 = RTC 执行侧本体）

pace 窗口必须 ≥ 单轮推理耗时，否则每轮配额消费完新块未就绪：

- **现役配速律下**：`hold`（默认）——hold 最后目标**单调收敛**（几何逼近永不过冲→无往复），夹爪行不变（chg 阈值抑制重发→无翻摆），逐 10ms 轮询**推理一落地立即换块**（轮询早退，不烧满剩余窗）。hold 窗是纯墙钟成本，平滑退化。连续 6 窗（`--hold-max`）未归=判定挂死停机。
- **stale 反例**（已存档 `legacy/run_g1_loop_stale.py`，仅 A/B 用）：旧 chunk 剩余步续航——pace 破水位时臂往复+夹爪翻摆。
- 同参数稳态两态行为一致（零 hold），pace 压破水位才分化——这是主对照实验设计。

**水位实测**：真机推理 ~320ms（bf16 + 取图，导航栈冻结）；极限 pace=0.33 不触发推理等待；pace=0.35 留 ~20ms 余量，真机稳。⚠ 导航栈醒着 +55ms/轮 → 水位 ~0.42，pace 须配 0.43（0.38/0.35 落判死区，9/30 六连跑 sweep 定案）。**pace/div 死区是水位函数**，换推理耗时（换图/换栈状态）须重扫。

## 5. 抖动的四层处理

| 抖动源 | 处理 |
|---|---|
| 指令边界换向（到点→重新起步的锯齿） | 配速律 div≥1.x 永不到点、速度不过零（§3）；settle 停走模式即根因，默认弃用 |
| 模型输出抖动（实测相邻行翻转 ~109 次/s，R 臂 ≈50%@2.7 mrad） | 近距阻尼：导程 `gap0 < near_gap(0.06 rad)` 时 div_eff 切 near_div(1.85)——低配速单调收敛，滤放置犹豫摆幅防过冲 |
| 近态单阈值泵动（增量在阈值两侧逐轮窄↔宽翻转 = 1.59×↔1.0× 速度方波往复摆动，10-13 实录） | near_exit 滞回：进态 near_gap、退态 2×near_gap，整段稳定驻留 |
| 抓住物体后撤段被近阻尼饿死（持物爬行 R 爪 0%） | near_bypass：抓取事件（爪开→合穿越）后 15 轮旁路近阻尼全速 |

可选 `--near-n N`：近态本轮配额/步宽缩到 N 步（近态吃最新观测的短导程；spc 小的配置慎开≈全程慢放）。退出自动回全宽（轮首重置）。

## 6. 换块如何修复摆动

摆动的块界来源 = 新块计划与臂当前态失配（重规划跳变 ∝ 观测陈旧度）。本设计的修复：

1. **帧 0 重锚**：`plan_step` 的目标永远是 `cur + clip(chunk绝对目标 − cur, ±BUDGET)`——新块第一条指令从**当前臂位**拉开，不是绝对重放；块界 |Δcmd| 被限幅钳住，无跳变。
2. **delta 基准随块走**：chunk 臂维是相对"预测时刻 state"的 delta（训练管线 relative_actions_processor 语义），换块时 `BASE_ARM` 更新为该块预测时刻臂位——基准错 = 机械臂镜像甩飞（9-23 实录）。
3. **抽帧在发令瞬间**：下轮取图发生在首条指令执行期（滑行中途）= 观测最新，重规划跳变最小化（观测新鲜度是接缝第一杠杆）。
4. **弃尾 + hold 单调收敛**：消费配额后的 chunk 剩余步永不喂；等推理时目标不动只收敛——两条路都不产生往复。
5. 再起步柔化：多窗 hold（臂真减速过）后 `--hold-ramp N` 轮臂速限幅 0.5→1.0 线性恢复（执行侧 crossfade，零推理成本）；1 窗轮询早退的 hold 不触发（臂未减速）。

（对照：traj 流式线的块界处理是另一套四态谱——追回回摆/anchor 停车/delay 攒滞后猛冲/blend 连续跨界，见 `run_g1_loop_traj.py`，不在本文范围。）

## 7. 速度衔接汇总

- **窗口间**：每条指令发令瞬间从当前 gap0 重算 pace_v——速度场连续，无到位门、无阻塞等待；
- **巡航↔近态切换**：div_eff 在 pace_div ↔ near_div 间切换，滞回（§5）防速度方波；
- **上下限**：clip(V_MIN=0.02, args.speed)；坡升系数 ramp_f 乘性叠加；
- **夹爪**：伴随 chunk 爪维下发，变化超 grip_chg(2%) 才发（非阻塞不等反馈），0.15 m/s（10-13 台架标定：伺服守约+起步死区 0.9s，回读新鲜 p50 10ms）。

## 8. 安全护栏（逐条指令生效）

| 护栏 | 语义 |
|---|---|
| delta_max 限幅 | 每条指令目标 = 当前读数 ± spc×delta_max（25×0.3=7.5 rad 封顶） |
| 漂移护栏 | 任一关节偏离起始位超 max_excursion(3.0 rad) → 立即停，臂留原地 |
| 包络护栏 | 整块绝对构型逐行查 joint_envelope，越界截该行前缀；行 0 越界或连续 N 轮越界（感知漂移）→ 停 |
| 残差预警 | 导程残差 ≥100 mrad 持续 3 段 → 提示疑似受阻（顶桌/卡物），人工 q 停 |
| 下发校验 | set_joint_positions 非 SUCCESS → 停机 |
| q 急停 | 后台监听线程，SDK 阻塞中也可退；物理急停第一优先级 |

每轮遥测：推理/取图/执行 ms、导程残差 mrad、相邻指令增量 |Δcmd|（抖动代理）、LatencyTracker 分位数汇总。

## 9. 参数表（config/g1.toml [loop] 现值，优先级 CLI > config > 内置）

| 参数 | 现值 | 语义 |
|---|---|---|
| chunk_size | 50 | 推理 chunk 长度（训练原生；勿与 lerobot RTC 的 execution_horizon 混淆） |
| n_action_steps (n) | 25 | 每轮消费步数（弃尾其余）；模拟频率公式中的 n |
| steps_per_command (spc) | 25 | 合步宽度：一条 SDK 指令跨 K 步（≤n 钳位；合步不跨 chunk） |
| pace | 0.35 | 指令窗口 s；须盖住推理水位（§4） |
| pace_div | 1.5 | 覆盖率旋钮：1=全程/2=半程；超频倍数=n/(pace×div)/30 |
| delta_max | 0.3 | 每步位移限幅 rad |
| speed | 1.0 | 配速上限 rad/s |
| near_gap / near_div | 0.06 / 1.85 | 近阻尼触发导程 / 近态配速系数 |
| near_exit | 0 (=2×near_gap) | 近态滞回退出阈值 |
| near_bypass | 15 | 抓取后旁路近阻尼轮数 |
| max_excursion | 3.0 | 漂移护栏 rad |
| hold_max / hold-ramp | 6 / 0 | hold 挂死上限窗 / 再起步坡升轮数 |

## 10. 已知边界

- `--fps` 勿带：改消费节拍=时间维 OOD → 包络停机（15Hz 事故实录）。
- 配速律只适用本接口（`set_joint_positions`+`speed_rad_s` 配速）；`set_joint_commands(tfs)` 路线底层是指数追踪 v≈k×gap（k≈2.6/s），另一套律，勿混用参数。
- spc>30 勿试（起停次数太少，单指令窗口内计划走形）；spc=15 是 0.95× 反例。
- pace 压水位以下不是提速是退化：hold 版=纯变慢，stale 版=往复+翻摆。
- 双构造/换 prompt 等任务编排见 `run_g1_task_pickplace.py` 与 loop 文件头，不在本文范围。
